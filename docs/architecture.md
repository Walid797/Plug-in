# معماری برنامه

## اصول

1. **هستهٔ خالص و آزمون‌پذیر:** همهٔ محاسبات حساس (چیدمان چاپ، PDF، DPI، ZIP، کادر، رنگ، ماسک، هندسهٔ چهره) در `src/core/` بدون وابستگی به مرورگر نوشته شده و با `node:test` آزمون می‌شود.
2. **یک هندسه برای همه:** خروجی موتور چیدمان (`computeLayout`) هم پیش‌نمایش، هم چاپ مرورگر و هم PDF را می‌سازد. پیش‌نمایش و چاپ از یک تابع DOM مشترک (`createSheetElement`) استفاده می‌کنند.
3. **یک خط لولهٔ رندر:** `renderPhoto` برای پیش‌نمایش ویرایشگر، پیش‌نمایش چاپ و خروجی نهایی یکسان است.
4. **غیرمخرب:** عکس اصلی بایت‌به‌بایت نگه داشته می‌شود؛ همهٔ ویرایش‌ها پارامترهای مستقل از وضوح‌اند (کادر نسبی، ضربه‌های قلم‌موی نسبی).
5. **صداقت در هوش مصنوعی:** هر قابلیت هوش مصنوعی فقط وقتی فعال است که مدل واقعی محلی موجود و سالم (چکسام) باشد؛ در غیر این صورت غیرفعال با دلیل فارسی.

## لایه‌ها

```
src/core/       منطق خالص: layout, pdf, binary (DPI/ZIP/CRC/امضای فایل), crop, adjust, mask, idphoto, presets, dates, digits, filenames, history
src/render/     renderPhoto (ترکیب لایه‌ها با Canvas 2D)، export (خروجی عکس با DPI)
src/print/      sheet: ورودی چیدمان، DOM برگه، چاپ مرورگر، PDF، تصویر برگه، کالیبراسیون
src/ai/         registry (مدل‌ها، چکسام، مجوز)، models (وضعیت/نصب)، runtime (MediaPipe / ONNX Runtime)، face، segment، companion
src/state/      store (وضعیت تغییرناپذیر + واگرد)، media (عکس‌ها، پیش‌نمایش‌ها، ماسک‌ها با کش محدود)، persist (ذخیرهٔ خودکار)
src/storage/    db: IndexedDB + OPFS + حالت حافظهٔ موقت
src/platform/   capabilities، image (بررسی/رمزگشایی امن)، worker (RPC)، download
src/workers/    عملیات سنگین (اصلاح ماسک، PDF، ZIP) — در Worker از Blob URL، با جایگزین رشتهٔ اصلی
src/ui/         Preact: پوسته، اجزا، بوم عکس، ۹ بخش
```

## جریان داده

```
فایل ← بررسی امضا و ابعاد ← رمزگشایی (با سقف پیکسل) ← نسخهٔ اصلی (حافظه/OPFS/IDB)
     ← پیش‌نمایش ≤۱۴۰۰ پیکسل (کش LRU) ← ویرایش (پارامترها در store)
     ← خروجی: رمزگشایی کامل ← renderPhoto با اندازهٔ دقیق ← JPEG/PNG (+DPI) یا PDF
```

## چیدمان چاپ (`src/core/layout.js`)

- واحد: ملی‌متر؛ مبدأ: گوشهٔ بالا-چپ کاغذ.
- برای اندازهٔ یکسان: شبکهٔ ساده، شبکهٔ چرخیده و همهٔ ترکیب‌های «دو بلوکی» (شبکهٔ اصلی + نوار چرخیده) ارزیابی و بهترین با این ترتیب انتخاب می‌شود: کمترین تعداد برگه ← کمترین عکس چرخیده ← سادگی.
- برای اندازه‌های مختلف: بسته‌بندی ردیفی (shelf) با حفظ ترتیب.
- تحمل عددی `1e-6` ملی‌متر تا حالت‌های «دقیقاً هم‌اندازه» (مثلاً ۹۴ = ۹۴) از دست نروند.
- خروجی: صفحه‌ها، جای هر عکس، تحلیل هر دو جهت (برای توضیح فارسی)، هشدارها و خطاها با کد.

## PDF (`src/core/pdf.js`)

نویسندهٔ PDF 1.4 بدون وابستگی؛ MediaBox/CropBox/TrimBox = اندازهٔ کاغذ به پوینت؛ هر عکس یک XObject (DCT) که با ماتریس `cm` بارها قرار می‌گیرد؛ خطوط برش برداری؛ برچسب‌ها به‌صورت تصویر Flate؛ `PrintScaling /None`.

## امنیت

- CSP: `script-src 'self' 'wasm-unsafe-eval'`، `connect-src` فقط خود برنامه و 127.0.0.1/localhost، `object-src 'none'`، `base-uri 'none'`.
- سرورهای محلی: فقط 127.0.0.1، فهرست مجاز پوشه‌ها، `realpath` برای جلوگیری از عبور از مسیر، فقط GET/HEAD، `nosniff`، COOP/COEP/CORP.
- فایل‌های واردشده هرگز اجرا نمی‌شوند؛ نوع با امضای بایت‌ها تعیین می‌شود؛ نام فایل‌ها از نویسه‌های کنترلی، جهت‌نمای پنهان (bidi) و نام‌های رزرو ویندوز پاک می‌شود.
- فایل JSON قالب‌ها با اعتبارسنجی سخت وارد می‌شود (فیلدهای ناشناخته حذف).
