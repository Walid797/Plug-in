# ساخت نسخهٔ ویندوز (exe) — نصب‌کننده با به‌روزرسانی، کاملاً آفلاین

این پوشه (`desktop/`) برنامه را در یک پوستهٔ Electron می‌گذارد و یک **نصب‌کنندهٔ ویندوز (Setup.exe)** می‌سازد. خود برنامه، فونت‌ها، موتورهای WASM و مدل‌های هوش مصنوعی داخل نصب‌کننده‌اند، پس بعد از نصب **بدون انترنت** کار می‌کند. ظاهر و کارکرد برنامه همان نسخهٔ وب است؛ فقط پنجرهٔ مستقل، آیکن روی دسکتاپ و منوی استارت دارد.

> وضعیت آزمون: پوسته (سرور محلی، پنجره، سرویس‌ورکر، جداسازی cross-origin، رابط فارسی) روی لینوکس با Electron واقعی اجرا و آزمون شد، و آزمون‌های واحد سرور آن در `npm test` هست. **ساخت خود Setup.exe روی ویندوز (GitHub Actions) و به‌روزرسانی خودکار هنوز اجرا نشده‌اند**؛ بار اول که ساختید نصب‌کننده را روی یک ویندوز تمیز امتحان کنید.

## راه ۱ — ساخت خودکار با GitHub (پیشنهادی، بدون نصب چیزی روی کمپیوتر)

۱. در GitHub: **Settings ← Actions ← General ← Workflow permissions ← Read and write permissions** را بزنید و ذخیره کنید.
۲. یک تگ نسخه بسازید و بفرستید (مثلاً از ترمینال):

```
git tag v1.0.1
git push origin v1.0.1
```

۳. در تب **Actions** کار «Windows installer (exe)» اجرا می‌شود (حدود ۵ تا ۱۰ دقیقه). در پایان در **Releases** فایل‌های `Hoshmand-Photo-Studio-Setup-1.0.1.exe` و `latest.yml` (و `.blockmap`) ساخته می‌شود. فایل `.exe` را دانلود و نصب کنید.
۴. برای هر نسخهٔ تازه فقط تگ بعدی را بسازید (`v1.0.2` …). برنامه‌های نصب‌شده خودشان نسخهٔ تازه را پیدا می‌کنند.

اگر مخزن **خصوصی (private)** باشد، به‌روزرسانی خودکار بدون توکن کار نمی‌کند؛ یا مخزن را عمومی کنید، یا فایل‌های Release را روی یک میزبان ساده (مثل همین سایت Render) بگذارید و در `desktop/package.json` بخش `build.publish` را به `{ "provider": "generic", "url": "https://نشانی-شما/updates/" }` تغییر دهید.

## راه ۲ — ساخت روی کمپیوتر خودتان (ویندوز)

پیش‌نیاز: Node.js نسخهٔ ۲۲ یا بالاتر. در پوشهٔ پروژه:

```
npm ci
node tools/build.mjs
cd desktop
npm install
npm run dist
```

فایل نصب‌کننده در `desktop\dist\Hoshmand-Photo-Studio-Setup-1.0.0.exe` ساخته می‌شود. برای اجرای آزمایشی بدون ساخت نصب‌کننده: `npm start` (داخل `desktop`).

## تنظیمات مهم (در `desktop/package.json`، بخش `build`)

| تنظیم | مقدار | معنی |
|---|---|---|
| `appId` | `af.hoshmand.photostudio` | شناسهٔ ثابت برنامه؛ **بعد از انتشار تغییرش ندهید** وگرنه به‌روزرسانی به برنامهٔ جدید جدا تبدیل می‌شود |
| `asar` | `false` | فایل‌ها بدون بسته‌بندی asar می‌مانند تا مدل‌های بزرگ و WASM مثل نسخهٔ وب خوانده شوند |
| `win.target` | `nsis`, `x64` | نصب‌کنندهٔ معمولی ویندوز ۶۴ بیتی |
| `nsis.oneClick` | `false` | کاربر می‌تواند پوشهٔ نصب را انتخاب کند |
| `nsis.perMachine` | `false` | نصب برای همین کاربر (نیازی به مجوز ادمین نیست و به‌روزرسانی بی‌مزاحمت است) |
| `nsis.deleteAppDataOnUninstall` | `false` | با حذف برنامه، پروژه‌ها و عکس‌های کاربر پاک نمی‌شود |
| `publish` | `github` | محل انتشار و محل بررسی نسخهٔ تازه |

داده‌های کاربر (پروژه‌ها، عکس‌های اصلی، تنظیمات، قالب‌ها، مدل‌های نصب‌شده) در پوشهٔ داده‌های برنامه (`%APPDATA%\Hoshmand Photo Studio`) می‌مانند و **با به‌روزرسانی از بین نمی‌روند**، چون برنامه همیشه روی همان نشانی ثابت `http://127.0.0.1:47877` اجرا می‌شود.

## آفلاین و به‌روزرسانی

- **آفلاین:** هیچ فایلی از انترنت لازم نیست؛ همهٔ مدل‌ها در نصب‌کننده‌اند.
- **به‌روزرسانی:** ۸ ثانیه بعد از باز شدن، اگر انترنت باشد، برنامه فقط فایل `latest.yml` را می‌خواند (هیچ عکس یا داده‌ای فرستاده نمی‌شود). اگر نسخهٔ تازه‌تر باشد آن را پس‌زمینه دانلود می‌کند و می‌پرسد «حالا راه‌اندازی مجدد» یا «بعداً» (با بستن برنامه نصب می‌شود). بدون انترنت یا بدون نسخهٔ تازه هیچ پیامی نمی‌دهد.
- **خاموش‌کردن بررسی نسخه:** فایل `%APPDATA%\Hoshmand Photo Studio\desktop-settings.json` را با این محتوا بسازید: `{ "autoUpdate": false }`. آن‌وقت برنامه هیچ اتصال انترنتی نمی‌سازد و برای نسخهٔ تازه باید Setup جدید را خودتان نصب کنید.
- نسخهٔ جدید را روی نسخهٔ قبلی نصب کنید؛ نیازی به حذف قبلی نیست.

## رفع مشکل «پس‌زمینه سفید نشد / تحلیل چهره ناموفق بود» (نسخهٔ ۱.۰.۳)

- **علت:** موتور هوش مصنوعی (MediaPipe) حتی روی پردازنده (CPU) هم عکس را با WebGL می‌خواند. Electron 37 (Chromium 138) دیگر وقتی درایور کارت گرافیک مسدود یا خراب است خودکار به گرافیک نرم‌افزاری برنمی‌گردد. پس روی بعضی کمپیوترهای ویندوزی WebGL نبود و حذف پس‌زمینه و تحلیل چهره با خطای `reading 'activeTexture'` شکست می‌خورد. همین خطا با خاموش کردن WebGL در Chromium بازسازی و آزمون شد.
- **رفع:** برنامه حالا با سوییچ `enable-unsafe-swiftshader` اجرا می‌شود تا در نبود کارت گرافیک، WebGL نرم‌افزاری (SwiftShader) به کار برود. «unsafe» دربارهٔ صفحه‌های ناشناس انترنت است؛ این پنجره فقط فایل‌های محلی خود برنامه را نشان می‌دهد.
- **پیام خطا:** اگر WebGL باز هم نبود، پیام دقیق «گرافیک (WebGL) این کمپیوتر در دسترس نیست» با راه حل نشان داده می‌شود.
- **ذخیره‌سازی ماندگار:** اجازهٔ `persistent-storage` داده شد، پس دکمهٔ «درخواست ذخیره‌سازی ماندگار» دیگر پیام «مرورگر درخواست را نپذیرفت» نمی‌دهد (در Electron آزمون شد: `persist()` → true).
- **بعد از به‌روزرسانی:** وقتی نسخه عوض می‌شود، فقط Service Worker و کش کد قدیمی پاک می‌شود تا کد تازه همان بار اول اجرا شود. پروژه‌ها، عکس‌ها، تنظیمات و مدل‌ها دست‌نخورده می‌مانند (در Electron آزمون شد).
- **آزمون نشده:** اجرای خود نصب‌کنندهٔ ۱.۰.۳ روی یک ویندوز واقعی بدون کارت گرافیک فعال.

## امنیت و حریم خصوصی

- سرور فقط روی `127.0.0.1` است و فقط پوشه‌های لازم را نشان می‌دهد (آزمون واحد: مسیرهای خارج از فهرست مجاز و پیمایش `..` رد می‌شوند).
- پنجره به نشانی دیگری نمی‌رود و لینک بیرونی باز نمی‌کند؛ فقط دوربین (برای عکس‌برداری داخل برنامه) می‌تواند اجازه بگیرد.
- اگر درگاه ۴۷۸۷۷ مشغول باشد، برنامه پیام می‌دهد و باز نمی‌شود (چون با درگاه دیگر، نشانی و در نتیجه داده‌های ذخیره‌شده عوض می‌شود).
- فقط یک نمونه از برنامه همزمان باز می‌شود.

## نکته‌های مهم

- **هشدار SmartScreen:** چون نصب‌کننده با گواهی امضای کد (Code Signing) امضا نشده، ویندوز در اولین اجرا «Windows protected your PC» نشان می‌دهد؛ «More info ← Run anyway». برای حذف هشدار باید گواهی امضای کد بخرید و در GitHub Secrets بگذارید (`CSC_LINK` و `CSC_KEY_PASSWORD`)؛ electron-builder آن را خودکار استفاده می‌کند.
- **حجم:** برآورد حجم نصب‌کننده ۱۲۰ تا ۱۸۰ مگابایت است (Chromium + برنامه + مدل‌ها؛ هنوز اندازه‌گیری نشده).
- **چاپ و PDF:** مثل نسخهٔ وب است؛ «چاپ» پنجرهٔ چاپ ویندوز را باز می‌کند و ذخیرهٔ فایل‌ها پنجرهٔ «Save as» می‌آورد. تنظیمات چاپگر Epson همان راهنمای `docs/print-calibration.md` است.
- **آیکن:** `desktop/build/icon.png` (۵۱۲×۵۱۲) است؛ برای آیکن دلخواه همین فایل را عوض کنید.
- تغییر کد برنامه: بعد از هر تغییر در `src/`، دوباره تگ تازه بسازید تا نصب‌کنندهٔ تازه ساخته شود.
